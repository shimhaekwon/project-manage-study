# 08. 통합·인수 테스트(UAT)

> **이 단계의 본질**: 개별 모듈을 합쳐 **전체 시나리오로 검증**하고, 발주사 사용자가 **인수 가능 수준**을 확인한다. UAT는 단순 시연이 아니라 **결함 발굴·합의·종결 사이클**이 돌아가야 한다. 일정 압축·결함 분류 모호함이 가장 흔한 사고.

---

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 목적 | 통합 시나리오 검증 + 발주사 인수 가능 수준 도달 |
| 핵심 산출물 | 통합/시스템/UAT 시나리오, 테스트결과서, 결함관리대장, 성능·보안 테스트 결과 |
| 표준 소요 | 2~6주 |
| 투입 인력 | QA 리드 1, QA 1~2, PM, PL, 발주사 사용자 N |
| 성공 신호 | UAT 통과 + Critical/High 결함 0건 + 발주사 인수 의향 표명 |

| ✅ 있어야 함 | 테스트시나리오 (시나리오·테스트케이스·수용 기준) | 06 설계 단계 산출물 |
| ⚠️ 권장 | 테스트 데이터 (실제 운영 유사) | 데이터 마스킹 또는 합성 |
| ❓ 확인 | 발주사 UAT 인력 가용성·일정 | 사전 합의 (UAT는 사용자 부담) |

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | QA 리드, QA, 개발자 (결함 수정) | 사용자 테스터 N명 |
| **A** 책임 | PM | 발주 PM |
| **C** 자문 | 보안·성능 전문가 | 정보화·현업 검토자 |
| **I** 보고 | 본부장 | CIO |

### When (언제)
- 단위테스트 종료 후 ~ 인수 직전 (2~6주)
- **순서**: 통합테스트(SIT) → 시스템테스트(ST, 성능·보안 포함) → 사용자 인수테스트(UAT)
- **일정 압축 주의**: UAT는 사용자 시간 확보 어려움 → 사전 일정 락인

### What (무엇을)
- **수행사가 작성·제출**: 테스트시나리오, 테스트결과서, 결함관리대장, 성능·보안테스트 결과
- **발주사가 수행·제공**: UAT 실시, 결함 보고, 사용자 의견
- **공동 의사결정**: 결함 분류·우선순위, UAT 통과 판정, 인수 조건

### Where (어디서)
- 테스트 환경: 별도 STG 서버 (운영 유사)
- UAT: 발주사 사무실 (대면 권장)
- 결함 등재: 합의된 이슈관리 시스템

### Why (왜)
- **결함 분류 모호 = 종결 무한 지연**. "Critical 인지 Major 인지" 사전 정의 필요.
- **발주사 UAT 참여 부족 = 검수 시점 폭탄**. UAT 단계에 발견되지 않은 결함이 검수 단계에서 터짐.
- **성능·보안 테스트 누락 = 오픈 직후 장애**.

### How (어떻게)
1. 테스트시나리오 검토·확정 (RTM 매핑)
2. 테스트 데이터 준비
3. SIT 실시 → 결함 등재·수정·재테스트
4. ST 실시 (성능·보안·장애·복구)
5. UAT 일정·환경·교육 사전 준비
6. UAT 실시 → 결함 등재·분류·합의
7. 결함 종결 사이클 (회귀 테스트 포함)
8. UAT 통과 판정 → 인수 조건 합의

## 4. ToDo 체크리스트

### 4-1. 사전 준비
- [ ] 테스트시나리오 검토·확정 (RTM 매핑 100%)
- [ ] 테스트 데이터 준비 (마스킹 또는 합성)
- [ ] 테스트 환경 점검 (외부 IF 연동·계정·권한)

- [ ] **UAT 통과 기준 사전 합의** (예: Critical 0건, High 0건, 핵심 시나리오 100% 통과)
- [ ] UAT 사용자 교육 자료 + 일정 합의

### 4-2. SIT (Sub System Integration Test)
- [ ] 모듈 간 통합 시나리오 실행
- [ ] 외부 시스템 연동 시나리오 (Mock → Real)
- [ ] 데이터 흐름 정합성 검증
- [ ] 결함 등재·수정·재테스트
- [ ] SIT 종료보고

### 4-3. ST (System Test)
- [ ] 성능 테스트 — 부하·스트레스·내구성 (NFR 정량값 기준)
- [ ] 보안 테스트 — 취약점 진단(OWASP Top 10), 인증·권한, 암호화
- [ ] 장애 복구 테스트 — DB 장애·네트워크 단절·서버 다운
- [ ] 호환성 테스트 — 브라우저·OS·디바이스
- [ ] 운영성 테스트 — 로그·모니터링·백업·배치

### 4-4. UAT
- [ ] UAT 사용자 교육 (1~2시간)
- [ ] UAT 일자별 시나리오 안내
- [ ] 결함 등재 채널 안내 (이슈관리 시스템 또는 양식)
- [ ] 일일 UAT 회의 (결함 분류·조치 결정)
- [ ] 결함 종결 사이클 (수정 → 재테스트 → 종결)
- [ ] **UAT 통과 판정** + 발주사 서명
- [ ] 잔존 결함 합의 (오픈 후 처리 / 차기 보완 / 면제)

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| UAT 일정 압축 (1주 → 3일) | 결함 미발견 → 검수 시 폭탄 | 계약 시점에 UAT 기간 명문화 + 사용자 시간 사전 락인 |
| 결함 분류 모호 ("이게 Critical?") | 종결 무한 지연 | 사전 정의 표 (§5-2) 합의 |
| UAT 통과 기준 미합의 | 통과 판정 분쟁 | 사전 정량 기준 합의 |
| 발주사 사용자 참여 부족 | 결함 미발견 | 임원 결재로 사용자 투입 강제 |
| 성능·보안 테스트 누락 | 오픈 직후 장애 | 단계 진입 시점 체크리스트 강제 |
| 회귀 테스트 누락 (결함 수정 후) | 다른 기능 깨짐 | 회귀 테스트 자동화 + CI 통합 |
| 잔존 결함 합의 누락 | "왜 이거 안 됐냐" 분쟁 | UAT 결과서에 잔존 결함 표·처리 방안 명시 |
