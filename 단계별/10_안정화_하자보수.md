# 10. 안정화 / 하자보수

> **이 단계의 본질**: **돈 못 받고 일하는 단계**. 안정화 기간은 검수 후 일정 기간 무상 운영 지원, 하자보수는 우리 귀책 결함만 무상 수정. **추가 기능 요청을 무상으로 받기 시작하면 차기 사업 견적 기준선이 무너진다.** 범위 통제가 PM의 90% 업무.

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | 안정화 PM, 개발자 (대기) | 운영팀, 현업 사용자 |
| **A** 책임 | PM | 발주 PM (또는 운영 책임자) |
| **C** 자문 | 본사 PMO, 법무 (분쟁 시) | 정보화팀장 |
| **I** 보고 | 본부장 | CIO |

### When (언제)
- 검수 합격 직후 ~ 하자보수 기간 종료
- **안정화**: 검수 후 1~3개월 (계약·관행)
- **하자보수**: 검수 후 1~3년 (사업 규모·계약)

### What (무엇을)
- **수행사가 작성·제출**: 안정화운영계획, 결함조치내역서, 월간보고서, 변경요청 회신서 (수용·반려)
- **발주사가 제공·요청**: 결함 보고, 변경 요청 (대부분이 추가 기능)
- **공동 의사결정**: 결함 vs 변경 분류, 변경의 유·무상 결정

### Where (어디서)
- 원격 지원 (이메일·VPN·이슈관리)
- 현장 지원 (긴급 시, 사전 합의)
- 월간 보고: 화상 또는 대면

### Why (왜)
- **안정화 무한 연장 = 후속 사업 인력 미투입 → 회사 수익성 악화**.
- **하자 vs 변경 분류 모호 = 무상 추가 기능 폭주**. 한 번 무상 처리하면 선례가 된다.
- **차기 사업 연결**: 안정화·하자 단계의 신뢰가 차기 RFP·수의계약으로 이어진다.

### How (어떻게)
1. 안정화운영계획 작성 (기간·인력·SLA·콜 채널)
2. 결함 보고 접수 → **결함 vs 변경 분류**
3. 결함 → 무상 수정 + 결함조치내역서
4. 변경 → 변경요청 회신서 (영향분석·견적·일정)
5. 월간보고 (결함 처리 내역·변경 처리 현황)
6. 안정화 종료 시점에 발주사 종료 합의서
7. 하자보수 기간 종료 시점에 종료 통보

### 5-2. 하자 vs 변경 분류 기준 (사전 합의 샘플)

| 구분 | 정의 | 처리 |
|---|---|---|
| **하자** | 인수일 기준 산출물·요구사항에 부합하지 않는 동작, 우리 귀책 | 무상 수정 |
| **하자 아님 (제외)** | (1) 발주사 환경 변경 (서버·DB·네트워크·OS), (2) 외부 시스템 변경, (3) 사용자 오조작 | 유상 또는 운영 영역 |
| **변경 (추가 기능)** | 인수일 기준 요구사항 외의 신규·개선 요청 | 변경요청 → 영향분석 → 유상 견적 |
| **변경 (개선)** | 기능은 동일하나 UI·성능 개선 | 변경요청 → 합의 후 유상 또는 차기 사업 |

> 분류 회색 지대는 **공동 검토 후 합의 문서화**. 한 번 무상 처리하면 선례가 됨.

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| 하자 vs 변경 분류 모호 | 추가 기능 무상 폭주 | 분류 기준표(§5-2) 사전 합의 + 회색 지대 공동 검토 |
| "이 정도는 그냥 해주세요" 무상 수용 | 선례 발생 → 차기 견적 기준 무너짐 | 1건도 회신서 발행 (수용 시에도 "호의로 1회" 명시) |
| 안정화 무한 연장 | 후속 사업 인력 미투입 | 종료일 명문화 + 종료 1주 전 통보 |
| 콜 채널 분산 (전화 직접·SNS·구두) | 추적성 상실·SLA 측정 불가 | 단일 채널 강제 (이슈관리 시스템) |
| 하자보수 종료 통보 누락 | 종료 후에도 콜 받음 | 종료 6개월 전·당일 공식 통보 |
| 운영 위탁 협의 지연 | 차기 사업 기회 상실 | 하자 종료 6개월 전 운영 계약 협의 시작 |
| 보안 사고 (수행사 계정 잔존) | 책임 분쟁 | 09에서 회수 + 안정화 기간 운영 계정만 사용 |

## 8. 역추적(Backfill) 가이드

10부터 진입(타사 검수 후 안정화·하자만 위탁)은 매우 드물지만:

| 누락 항목 | 보완 방법 |
|---|---|
| 검수확인서 미보유 | 발주사·전임사로부터 사본 입수 + 검수일·잔존 사항 확인 |
| 산출물·소스코드 미인수 | 전임사로부터 일괄 인수 + 누락분 표 작성 |
| 인수인계 부실 | 발주사·전임사 합석 미팅 — 운영 절차·계정·외부 IF 인수 |
| 하자 vs 변경 기준 미합의 | 진입 즉시 양측 합의 (§5-2 기반) |
| 콜 채널 분산 | 단일화 협의 + 이전 채널 회수 |
