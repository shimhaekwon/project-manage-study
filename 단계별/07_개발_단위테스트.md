# 07. 개발 / 단위테스트

> **이 단계의 본질**: 설계를 코드로 옮긴다. 가장 긴 단계이며 **진척률 신뢰성·코드 품질·결함 추적**이 PM의 3대 과제. 형상관리·코드리뷰·단위테스트가 빠지면 08 통합테스트에서 폭발한다.

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | PL, 개발자, QA, DevOps | (관여 적음, 주간보고 수신) |
| **A** 책임 | PM | 발주 PM |
| **C** 자문 | 아키텍트, 보안 | 정보화 검토자 |
| **I** 보고 | 본부장 | CIO (월간 운영위) |

### When (언제)
- 설계 종료 직후 ~ 단위테스트 완료 (8~24주)
- **첫 주: 환경·표준 정비** (브랜치 전략·코드리뷰 절차·CI 파이프라인)
- **모듈 단위 진척**: 사전 합의된 모듈 착수 순서 준수
- **마지막 1~2주: 단위테스트 완료·통합 준비**

### What (무엇을)
- **수행사가 작성·제출**: 소스코드, 형상관리계획서, 단위테스트결과서, 주간보고서, 결함관리대장, 진척현황
- **발주사가 제공·검토**: 환경 권한, 주간보고 검토, 변경 승인
- **공동 의사결정**: 변경요청 처리, 일정 조정, 우선순위 변경

### Where (어디서)
- 개발: 수행사 작업실 (보안 사업은 발주사 상주)
- 형상관리: Git (GitLab·GitHub·Bitbucket)
- 이슈관리: JIRA·Redmine·GitHub Issues
- 문서: Confluence·Notion·SharePoint

### Why (왜)
- **진척률 자기보고 신뢰 문제** — 코드량·완료율 자체보고는 부풀려짐. 객관 지표 필요.
- **형상관리 누락 = 작업 손실 + 책임 소재 불명**.
- **코드리뷰·단위테스트 부재 = 통합테스트 폭주** (08 단계 결함 1건당 분석·수정·재테스트 비용은 단위테스트 단계의 5~10배).

### How (어떻게)
1. 첫 주 — 환경·표준·CI·브랜치 전략·코드리뷰 절차 정비
2. 모듈 착수 순서 합의 (사전 결정 + 변경 금지)
3. 개발자별 작업 할당 + 일일 스탠드업
4. 코드리뷰 (PR 단위, 최소 1인 승인)
5. 단위테스트 작성 (커버리지 목표 70~80%)
6. CI 자동 빌드·테스트
7. 주간보고 (진척률·이슈·리스크·다음주 계획)
8. 결함은 발견 즉시 결함관리대장 등재

## 5. 핵심 산출물 + 샘플

> 샘플은 모두 `샘플프로젝트_고객Q&A시스템.md` (Helpdesk Lite) 기준.

### 5-1. 주간보고서 표준 항목

| 항목 | 내용 |
|---|---|
| 보고 기간 | 2026-08-04 ~ 2026-08-08 (제N주차) |
| 전체 진척률 | 계획 35% / 실적 33% (-2%, **YR**) |
| 분야별 진척 | 문의 등록 80 / 답변 70 / 검색 40 / SLA 알림 30 / 통계 0 |
| 이번 주 실적 | (3~5 bullet, 모듈·완료 항목) |
| 다음 주 계획 | (3~5 bullet, 모듈·목표) |
| 이슈 | 신규 1건 (이슈ID), 진행 중 2건, 종결 1건 |
| 위험 | 신규 0건, 진행 중 1건 (위험ID) |
| 변경 | 신규 변경요청 1건 (변경ID, 영향 검토 중) |
| 의사결정 요청 | 1건 (사내 SMTP 서버 사양 미공개, 발주사 인프라팀 회신 필요) |
| 첨부 | 진척표, 결함현황, 위험관리대장 |

> 색상 표기: **GR**(녹색, 정상), **YR**(황색, 주의), **RD**(적색, 즉시 조치 필요)

### 5-2. 결함관리대장 표준 항목

| # | 결함ID | 발견일 | 모듈 | 심각도 | 우선순위 | 재현 절차 | 원인 | 조치 | 조치자 | 검증자 | 상태 | 종결일 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | DEF-INQ-007 | 2026-08-05 | SLA 알림 | High | P1 | NEW 문의 24h 경과 후 알림 미발송 | 배치 스케줄러 cron 표기 오류 | cron 식 보정 + 단위테스트 추가 | 김OO | 박OO | Closed | 2026-08-07 |

**심각도**: Critical / High / Medium / Low
**우선순위**: P1 (즉시) / P2 (이번 주) / P3 (이번 단계 내) / P4 (백로그)
**상태**: Open / Assigned / Fixed / Verified / Closed / Reopened

### 5-3. 단위테스트결과서 표준 항목

| 모듈 | 테스트케이스 수 | 통과 | 실패 | 보류 | 통과율 | 라인 커버리지 | 분기 커버리지 | 비고 |
|---|---|---|---|---|---|---|---|---|
| inquiry-core | 142 | 138 | 0 | 4 | 97.2% | 82% | 75% | 보류 4건은 SMTP 의존 |
| inquiry-sla-notifier | 56 | 56 | 0 | 0 | 100% | 91% | 88% | — |
| user-auth | 89 | 87 | 2 | 0 | 97.8% | 78% | 70% | 실패 2건 결함등재 |

### 5-4. 형상관리계획서 핵심

| 항목 | 표준 |
|---|---|
| 저장소 | Git (GitLab) — `prj-{프로젝트코드}` |
| 브랜치 전략 | `main` (운영) / `develop` (통합) / `feature/{이슈ID}-설명` / `hotfix/{이슈ID}` |
| 커밋 메시지 | `[이슈ID] type: 요약` (type: feat/fix/refactor/test/docs/chore) |
| PR 정책 | feature → develop, 최소 1인 승인 + CI 통과 |
| 태그 | 버전 출시 시 `v{major}.{minor}.{patch}` |
| 릴리즈 노트 | 태그별 자동 생성 + 수기 보강 |

### 5-5. 진척률 객관 지표 (자기보고 보완)

| 지표 | 계산 |
|---|---|
| EVM 기반 | EV (완료된 WBS 가중치) ÷ 계획값 |
| 머지 PR 수 | 모듈별 완료 PR ÷ 계획 PR |
| 단위테스트 통과 수 | 통과한 테스트케이스 ÷ 계획 테스트케이스 |
| 커버리지 도달 | 라인 커버리지 ÷ 목표 커버리지 |
| 결함 종결율 | Closed ÷ (Open + Closed) |

> "70% 완료" 자기보고만 받지 말고, 위 지표 중 2~3개를 동시에 본다. 수치가 발산하면 자기보고 부풀림.

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| 진척률 자기보고 부풀림 | 종료 직전 폭탄 | 객관 지표 (§5-5) 동시 운영 |
| 형상관리 미흡 (직접 서버 수정) | 작업 손실·책임 불명 | 첫 주 브랜치·PR 정책 강제 |
| 코드리뷰 형식적 통과 | 결함 누적 | 리뷰 체크리스트 + 임원 샘플링 |
| 단위테스트 미작성 | 통합테스트 결함 폭주 | 커버리지 70~80% 강제 + CI Gate |
| 변경요청 무절차 수용 | 일정 와해 | 변경요청서·영향분석·승인 강제 |
| 결함을 결함대장에 등재하지 않고 처리 | 추적성 상실 | 발견 즉시 등재 의무화 |
| 발주사 환경 의존 (계정·VPN·IF) 지연 | 개발 정체 | 의존성 표 + 매주 갱신 |

## 7. 종료 조건 (Exit Criteria)

- [ ] 모듈별 단위테스트 통과율 ≥ 95% (목표치는 사전 합의)
- [ ] 코드 커버리지 ≥ 70% (라인 기준, 목표치는 사전 합의)
- [ ] 결함관리대장 — Critical 0건, High 0건, Medium ≤ N건
- [ ] 모든 모듈 형상관리 등록·태그 부여
- [ ] 통합테스트 환경 준비 완료
- [ ] 마일스톤 3 검수

## 8. 역추적(Backfill) 가이드
