# 09. 인수인계 / 오픈 / 검수

> **이 단계의 본질**: **돈을 받는 단계**. 산출물 인계·시스템 컷오버·검수 확인·대금 청구의 4중 사이클을 통과해야 한다. 산출물 1건이라도 누락되면 검수가 1~3개월 늘어진다. **검수확인서 서명일 = 우리 매출 인식 시점**.

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | PM, PMO, PL, DevOps | 발주 PM, 정보화, 운영팀 |
| **A** 책임 | 수행 임원 | 발주 책임자 (검수 승인) |
| **C** 자문 | 보안·법무 | 감리, 외부 자문 |
| **I** 보고 | 본부장, 대표 | CIO, 사업본부장 |

### When (언제)
- UAT 통과 직후 ~ 검수 완료 (2~4주)
- **컷오버**: 휴일·심야 (업무 영향 최소)
- **검수 의뢰**: 컷오버 후 안정화 1~2주 권장

### What (무엇을)
- **수행사가 작성·제출**: 산출물목록·산출물 일괄, 검수의뢰서, 인수인계서, 사용자교육자료, 컷오버계획서, 데이터이행결과서, 운영 매뉴얼
- **발주사가 수행·교부**: 검수 실시, 검수확인서 서명, 대금 지급 처리
- **공동 의사결정**: 컷오버 일시, 롤백 기준, 검수 통과·반려, 잔존 작업 처리

### Where (어디서)
- 컷오버: 발주사 운영 환경
- 인수인계: 발주사 사무실 (대면 권장, 운영팀 합석)
- 검수: 발주사 정해진 절차

### Why (왜)
- **산출물 누락 = 검수 반려·지연 = 대금 지연**.
- **컷오버 실패 = 업무 중단 = 신뢰 붕괴**. 롤백 기준·시간 사전 합의.
- **검수확인서 서명 지연 = 매출 인식 지연 + 하자보수 시작 지연**.
- **운영 인계 부실 = 안정화·하자보수 단계 무한 콜**.

### How (어떻게)
1. 산출물 목록 최종화 + 발주사 합의
2. 모든 산출물 v1.0 확정 + 변경이력 정리
3. 컷오버 계획서 (작업·시간·롤백·연락처)
4. 데이터 이행 (사전 리허설 → 본 이행 → 검증)
5. 컷오버 실시 (체크리스트 기반)
6. 사용자 교육 (1~2일)
7. 운영 인계 (운영팀에 매뉴얼·계정·런북 인계)
8. 검수 의뢰 → 검수 → 검수확인서 서명
9. 대금 청구 → 입금 확인

### 5-2. 검수확인서 표준 양식

```
검수확인서

1. 사업명: ○○○ 시스템 구축 사업
2. 계약번호: 2026-XXX
3. 계약기간: 2026-01-01 ~ 2026-12-31
4. 검수 대상
   가. 산출물: 별첨 산출물 목록 N건
   나. 시스템: 별첨 시스템 구성도
5. 검수 기간: 2026-12-15 ~ 2026-12-22
6. 검수 결과: 합격 / 조건부 합격 / 불합격
   - 합격 사유 또는 조건 (있는 경우)
7. 잔존 사항 (조건부 합격 시): 별첨 잔존사항 목록
8. 검수 의견:
   (자유 기술)

위와 같이 검수를 완료하였음을 확인합니다.

2026년 12월 22일

발주사: (사업명) 사업본부장 ○○○ (서명)
수행사: (회사명) 사업총괄임원 ○○○ (서명)
```

### 5-4. 인수인계서 표준 목차

```
1. 시스템 개요 (구성도·기술스택·외부 IF)
2. 계정·권한 인계 (관리자·서비스 계정·SSH·DB)
3. 운영 절차
   3.1 배포 / 3.2 롤백 / 3.3 모니터링 / 3.4 백업·복구
   3.5 정기작업 (배치·점검) / 3.6 장애 대응 (등급별 절차)
4. 알려진 이슈 + 대응 방법
5. 변경 이력 (최근 6개월)
6. 외부 연락처 (벤더·솔루션사·인프라사)
7. 핵심 인력 연락처 (수행사 측 안정화 기간 동안)
부록: 운영 매뉴얼, 사용자 매뉴얼, 장애 런북
```

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| 산출물 1건 누락 → 검수 반려 | 대금 지연 1~3개월 | 산출물 목록 사전 합의 + 인수증 받기 |
| 컷오버 롤백 기준 미합의 | 장애 시 결정 지연 → 피해 확대 | 컷오버 계획서에 정량 기준 명문화 |
| 데이터 이행 정합성 검증 부재 | 운영 시 데이터 깨짐 | 사전·본·사후 검증 + 차이 보고서 |
| 사용자 교육 부실 | 오픈 후 헬프데스크 폭주 | 1~2일 대면 + FAQ + 동영상 |
| 운영 인계 부실 | 안정화·하자보수 단계 무한 콜 | 운영팀 1~2일 합석 트레이닝 |
| 검수 일정·승인 라인 모호 | 검수 무한 지연 | 04 계약 시점 명문화 + 검수의뢰 시점 재확인 |
| 잔존 사항 합의 부실 | "이거 왜 안 됐냐" 분쟁 | 잔존사항 목록·처리방안·일정 별첨 |
| 수행사 운영 계정 미회수 | 보안 사고 시 책임 | 검수 후 즉시 계정 회수·로그 보관 |

## 8. 역추적(Backfill) 가이드

검수·인수인계만 별도 위탁(09부터 진입)한 경우 (감리·PMO·전환 위탁 형태):

| 누락 항목 | 보완 방법 |
|---|---|
| 산출물 인수 부족 | 전임 수행사로부터 산출물 일괄 인수 + 누락분 표 작성 |
| 시스템 정보 부족 | 전임사·발주사로부터 인프라·계정·외부 IF 정보 인수 (인수인계서 받기) |
| 검수 기준 모호 | 04 계약 조항 + 발주사 검수 절차 재확인 |
| 데이터 이행 계획 부재 | 1~2주 별도 작업 (현행 → 신규 매핑 + 리허설) |
| 운영팀 미식별 | 발주사 임원 결재로 운영팀 지정 요청 |
