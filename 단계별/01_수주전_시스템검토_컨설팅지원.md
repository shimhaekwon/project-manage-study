# 01. 수주 전 — 시스템 검토 / 컨설팅 지원

> **이 단계의 본질**: 발주사가 사업화를 결정하기 **전** 단계. 우리는 무상 또는 소액 유상으로 현황을 진단하고 방향을 자문한다. **목표는 단기 매출이 아니라 차기 본 사업 수주를 위한 사전 포지셔닝**.

---

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 목적 | 발주사 신뢰 확보 + 본 사업(03 제안) 진입 시 정보 우위 확보 |
| 핵심 산출물 | 현황진단보고서, 컨설팅 제안서, NDA |
| 표준 소요 | 2~6주 |
| 투입 인력 | PreSales PM 1명 + 컨설턴트 1~2명 (시간제) |
| 성공 신호 | 발주사가 **RFP 작성 자문(02)** 또는 **본 사업 RFP 발행** 으로 연결 의사 표명 |

## 2. 진입 조건 (Entry Criteria)

| 구분 | 항목 | 없으면? |
|---|---|---|
| ✅ 있어야 함 | 발주사 1차 컨택 채널 (담당자 명함·이메일) | 영업이 먼저 채널 확보 |
| ✅ 있어야 함 | 발주사가 검토 의뢰한 **현안 1줄 정의** ("ERP 노후화", "수기 업무 자동화" 등) | 첫 미팅에서 청취·기록 |
| ⚠️ 권장 | NDA 체결 (양방향) | **첫 자료 수령 전** 반드시 체결 |
| ❓ 확인 | 발주사의 **예산 단계** (검토만 / 예산 신청 중 / 확보 완료) | 첫 미팅에서 우회 질문으로 파악 |

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | PreSales PM, 컨설턴트 | 정보화 담당자, 현업 키맨 1~2명 |
| **A** 책임 | 영업 임원 | 정보화팀장 |
| **C** 자문 | 솔루션 아키텍트, 도메인 전문가 | 외부 자문(필요시) |
| **I** 보고 | 본부장 | CIO 또는 본부장 |

### When (언제)
- 발주사 사업화 검토 시점 ~ RFP 작성 착수 직전
- **소요**: 2~6주. 6주 넘기면 발주사 의사결정 동력이 떨어진다.

### What (무엇을)
- **수행사가 작성**: 현황진단보고서, 개선방향 자문메모, 컨설팅 제안서, NDA
- **발주사로부터 받음**: 현행 시스템 자료(권한 범위 내), 조직도, 업무 흐름 자료
- **공동 의사결정**: 사업화 가능성, 예산 규모(밴드), 일정 타당성

### Where (어디서)
- 발주사 사무실 1차 인터뷰 (대면)
- 우리 회사 회의실 또는 화상회의 (후속)
- 자료 공유: **별도 공유 폴더**(우리 환경) — 발주사 메일 첨부로 받지 말 것 (보안·증빙)

### Why (왜)
- 본 사업(03 제안) 시점에 우리만 도메인을 알고 있는 **정보 우위** 확보
- 발주사 키맨과 신뢰 관계 형성 → 평가 시 우호적 환경
- **부정당 회피**: RFP 작성에 직접 관여하면 입찰 자격이 박탈될 수 있다 (한국 공공·일부 민간). 컨설팅 → RFP 자문 → 제안 참여의 **경계선**을 의식해야 한다.

### How (어떻게)
1. NDA 체결 → 자료 수령
2. 1차 인터뷰 (1~2시간) — 6하원칙으로 청취, 녹음(승낙 시) + 인터뷰결과서 작성
3. 데스크 리서치 (벤치마킹 2~3건, 시장 동향 1건)
4. 현황진단보고서 초안 → 발주사 검토 미팅 → 확정
5. 컨설팅 제안서 (유상 컨설팅 또는 본 사업 RFP 자문 연결 제안)

---

## 4. ToDo 체크리스트

- [ ] 발주사 1차 미팅 일정 확정
- [ ] **NDA 체결** (양방향, 정보 보호 + 우리 노하우 보호)
- [ ] 1차 인터뷰 시 6하원칙 질문지 사전 준비 (아래 §5 샘플)
- [ ] 인터뷰 직후 24시간 내 **인터뷰결과서** 작성·발주사 확인 회신
- [ ] 자료 수령 채널 (별도 폴더) 안내·합의
- [ ] 현황진단보고서 초안 (10~20페이지)
- [ ] 발주사 키맨에게 초안 검토 미팅 요청
- [ ] 최종 보고 후 **다음 단계(02 RFP 자문 / 03 제안 / 종료) 의사 확인**
- [ ] 무상 컨설팅 종료 시점 명문화 (질질 끌리지 않게)

## 5. 핵심 산출물 + 샘플

### 5-1. 현황진단보고서 표준 목차

```
1. 사업 개요
   1.1 의뢰 배경 / 1.2 진단 범위 / 1.3 진단 방법
2. As-Is 현황
   2.1 조직 / 2.2 업무 프로세스 / 2.3 시스템 구성도 / 2.4 데이터 현황
3. 문제점 진단
   3.1 정량 지표 (처리시간·오류율·인건비 등) / 3.2 정성 지적사항
4. To-Be 방향
   4.1 개선 시나리오 / 4.2 개략 아키텍처 / 4.3 단계별 로드맵
5. 사업화 검토
   5.1 예산 밴드 (최소~최대) / 5.2 일정 가이드 / 5.3 리스크
6. 다음 단계 제안
   6.1 RFP 작성 자문 / 6.2 PoC 제안 / 6.3 본 사업 RFP 발행 시점
부록: 인터뷰 결과서, 벤치마킹, 참고문헌
```

### 5-2. 인터뷰 질문지 샘플 (6하원칙)

| 구분 | 질문 |
|---|---|
| Why | 왜 지금 이 검토를 시작하셨습니까? (트리거 이벤트) |
| Who | 의사결정 라인이 어떻게 됩니까? 최종 승인자는? |
| When | 사업화 목표 시점은? 제약 일정(법규·결산·인사)은? |
| What | 우선순위 1·2·3 기능은? 제외 범위는? |
| Where | 인프라(클라우드·온프레미스·하이브리드) 방향성은? 통합 대상 시스템은? |
| How | 예산 배정 방식은(자체·정부지원·외부)? 운영은 자체·위탁? |

### 5-3. NDA 핵심 조항 (샘플)

| 조항 | 핵심 |
|---|---|
| 비밀정보 정의 | "구두·서면·전자 등 형태 불문하고 일방이 비밀로 표시하거나 합리적으로 비밀임이 명백한 정보" |
| 비밀유지 기간 | 계약 종료 후 3년 (또는 5년) |
| 예외 | 공지된 정보, 독자 개발 정보, 법령상 공개 의무 정보 |
| 위반 시 | 손해배상 + (필요시) 위약벌 |
| 산출물 귀속 | 컨설팅 산출물의 저작권 귀속 명시 (수행사 보유 + 발주사 사용권) |

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| 무상 컨설팅에 인력 과투입 | 적자 + 본 사업 가격 협상력 약화 | 투입 한도(맨먼스) 사전 산정 + 초과 시 유상 전환 제안 |
| NDA 미체결 자료 수령 | 정보 보안 사고 시 책임 분쟁 | **자료 수령 전** 반드시 체결, 양방향 |
| RFP 직접 작성·기재 | 입찰 자격 박탈 (특히 공공) | 02 단계로 넘어갈 때 **자문/검토 형태만** 유지, 직접 타이핑 X |
| 현황진단을 발주사 임의 사용 | 보고서 가치 0, 차기 사업 우위 상실 | NDA에 **발주사 내부 사용 한정** 명시 |
| 키맨 1명에만 의존 | 그 사람 인사이동 시 관계 리셋 | 정보화팀장·현업·임원 **3-Layer** 접촉 유지 |

## 7. 종료 조건 (Exit Criteria)

다음 중 하나가 충족되면 본 단계 종료:

- [ ] 발주사가 **02 RFP 작성 자문** 의뢰 (유상 또는 무상 약정)
- [ ] 발주사가 **본 사업 RFP 발행 일정** 공유 (→ 03 제안 단계로 직행)
- [ ] 발주사가 **사업화 보류** 결정 (→ 관계 유지하며 종료, 6개월 후 리컨택)

## 8. 역추적(Backfill) 가이드

본 단계가 사실상 처음 시점이므로 역추적 대상이 없다. 단, 다음과 같은 경우 보완:

| 상황 | 보완 방법 |
|---|---|
| 영업이 NDA 없이 자료를 이미 받아온 경우 | 즉시 NDA 체결 + 받은 자료 목록을 NDA 첨부로 명시 |
| 발주사가 컨설팅 결과만 받고 RFP를 다른 사 자료로 작성 중 | **02 단계로 넘어가기 어려움** → 03 제안 단계 진입 시 도메인 우위 살리기 |
