# 03. 제안 — 제안서 작성 / PT

> **이 단계의 본질**: RFP를 받아 **수주를 위한 정식 입찰**에 들어간다. 가장 흔한 진입점이며, **수주 후 모든 책임의 출발점**이다. 무리한 약속은 향후 모든 단계의 폭탄이 된다.

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | 제안 PM, 솔루션 아키텍트, 컨설턴트, 견적 담당, 제안PT | RFP 담당자, 평가위원회 |
| **A** 책임 | 영업 임원, 수행 임원 | 발주 책임자 |
| **C** 자문 | 법무, 인사(투입 인력 가용성) | — |
| **I** 보고 | 본부장, 대표 | CIO |

### When (언제)
- RFP 수령 ~ 제안 마감 ~ 발표 ~ 우선협상자 선정
- **소요**: 2~4주 (제안서 작성) + 1~2주 (평가 결과 대기)

### What (무엇을)
- **수행사가 제출**: 제안서(기술·관리·가격), 견적서, 제안발표자료, 인력투입계획서, 회사소개서, 자격증빙
- **수행사가 받음**: RFP, 부속자료, 사전설명회 자료, 질의응답 회신
- **공동 의사결정** (협상 단계): 가격, 일정, 산출물 범위 미세조정

### Where (어디서)
- 제안서 작성: 우리 회사 (제안 작업실 또는 별도 공간)
- 사전설명회: 발주사 또는 온라인
- 제안 발표: 발주사 평가장 또는 온라인

### Why (왜)
- 제안서는 **수주 후 계약·수행의 기준 문서**가 된다. 무리한 약속은 04~10 모든 단계의 부담.
- 평가는 **기술 80~90% / 가격 10~20%** 가 일반적 — 가격으로만 승부하면 적자.
- 발표(PT)는 **신뢰성·전문성** 평가 — 핵심 인력이 직접 발표.

### How (어떻게)
1. RFP 분해 → 요구사항 ID 부여 (FR-001, NFR-001 등) → **요구사항 추적표(RTM) 초안**
2. 질의서 작성·제출 → 회신 수령
3. 제안 전략 회의 (Win Theme 3개 도출)
4. 제안서 작성 (기술·관리·가격 분야 병렬)
5. 내부 리뷰 (체크리스트 기반)
6. 발주사 제출 (마감 시간 24시간 전 제출 권장)
7. 발표 리허설 2회 → 발표
8. 우선협상자 선정 → 04 단계로

## 5. 핵심 산출물 + 샘플

### 5-1. 제안서 표준 목차 (한국 SI 표준)

```
[기술제안서]
1. 제안 개요 (회사 소개·사업 이해·Win Theme)
2. 사업관리 부문
   2.1 추진 체계 (조직·역할·RACI) / 2.2 일정 (WBS·마일스톤)
   2.3 품질관리 / 2.4 위험관리 / 2.5 보안관리 / 2.6 변경관리
3. 기술 부문
   3.1 시스템 아키텍처 / 3.2 적용 기술·표준 / 3.3 개발 방법론
   3.4 기능 요구사항 충족 방안 (FR-001~ 매트릭스)
   3.5 비기능 요구사항 충족 방안 (성능·보안·가용성)
   3.6 데이터 / 3.7 인터페이스 / 3.8 인프라
4. 구현 방안
   4.1 분석·설계·개발·테스트 단계별 접근 / 4.2 산출물 / 4.3 검증
5. 지원 부문
   5.1 교육 / 5.2 인수인계 / 5.3 안정화 / 5.4 하자보수
6. 기대효과 / 7. 회사 일반사항 / 부록 (실적·인증·인력 이력서)

[가격제안서]
별도 봉인 — 인건비·경비·이윤 분리 표기
```

### 5-2. 견적 산정 샘플 (소형 SI 기준)

| 항목 | 산정 |
|---|---|
| 직접인건비 | 등급별 단가 × 인원 × 개월 (정통부 SW기술자 노임단가 기준 가능) |
| 직접경비 | 출장·교육·라이선스·외주·테스트·재료비 |
| 간접비 | 직접인건비의 110~120% (회사 표준) |
| 기술료 | (직접인건비 + 간접비) × 20~40% |
| **합계** | 위 4항 합산 + 부가세 |

> 💡 **저가 입찰 경고선**: 예정가격의 60% 미만은 **수행 불가 + 검수 분쟁 + 차기 단가 하락**의 3중고.

### 5-3. 제안서 내부 리뷰 체크리스트

| 분류 | 점검 |
|---|---|
| 형식 | 페이지 한도·폰트·여백·표지·목차 RFP 준수 |
| 자격 | 입찰 자격·실적·인증 증빙 첨부 |
| 응답 | RFP 모든 요구사항(FR/NFR) 응답 매트릭스 |
| 일관성 | 제안서·견적서·발표자료 수치/일정 일치 |
| 가용성 | 제안 인력의 수행 시점 가용성 사전 확인 |
| 책임 | 면책·하자·지체상금·손해배상 한도 검토 |
| 증빙 | 평가위원이 검증 가능한 형태 (실적증명서·인증서) |

### 5-4. 발표(PT) 권장 구성 (20분 기준)

| 시간 | 내용 |
|---|---|
| 0~3분 | Win Theme + 사업 이해 |
| 3~10분 | 기술 접근 (아키텍처·차별화 포인트) |
| 10~15분 | 사업관리 (일정·인력·리스크) |
| 15~18분 | 기대효과·지원 |
| 18~20분 | 마무리 메시지 |
| 별도 10~20분 | 질의응답 |

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| 무리한 일정 약속 | 수행 단계 야근·품질 저하·검수 지연 | 견적 시점에 표준 산정 기준 사용, "가능합니다" 남발 금지 |
| 제안 인력과 실제 투입 인력 불일치 | 발주사 신뢰 붕괴 + 인력 교체 분쟁 | 제안 인력은 **실제 투입 가능자**만 기재 + 교체 시 동급 명문화 |
| 책임 한도 미협상 | 분쟁 시 무한 책임 | 손해배상 한도 = 계약금액 (또는 일부) 명문화 협상 |
| 가격을 너무 낮춰 수주 | 적자 + 추가 과업 무상 요청 받기 쉬워짐 | 견적 마지노선 사전 설정 + 임원 승인 |
| RFP 모호 항목을 우리 해석으로 답변 | 검수 시점에 "이건 그 뜻이 아니었다" | 질의서로 사전 명확화 + 답변에 가정·전제 명시 |
| 제안서·견적서·발표자료 수치 불일치 | 평가 감점·신뢰 하락 | 마감 전날 **숫자 일치 검토** 1회 별도 |
