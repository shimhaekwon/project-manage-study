# 11. 운영 / 차기 인계

> **이 단계의 본질**: 운영은 **별도 계약** (개발 계약과 구분). SLA·KPI 기반 정액 또는 단가 운영. 차기 인계는 **선의의 협조 의무**와 **노하우 보호**의 균형. 인계 부실은 차기 입찰에서 우리가 당할 미래의 모습.

## 3. 6하원칙 가이드

### Who (누가)

| 역할 | 수행사 측 | 발주사 측 |
|---|---|---|
| **R** 실무 | 운영 PM, 운영 인력 (운영자·DBA·DevOps·헬프데스크) | 발주 PM, 현업 사용자 |
| **A** 책임 | 운영 임원 | 정보화 책임자 |
| **C** 자문 | 보안·법무 | 외부 감리 |
| **I** 보고 | 본부장 | CIO, 사업본부장 |

### When (언제)
- 하자보수 종료 후 운영 계약 시작 (또는 검수 직후 운영 동시 시작)
- **계약 갱신**: 1년 단위 권장
- **차기 인계**: 계약 종료 3~6개월 전 협의 시작

### What (무엇을)
- **수행사가 작성·제출**: 운영계획서, SLA보고서(월간), 변경관리대장, 장애보고서, 정기점검 보고서, 차기인수인계서 (계약 종료 시)
- **발주사가 제공·요청**: 변경 요청, 장애 신고, 사용자 의견, 차기 사업자 정보 (인계 시)
- **공동 의사결정**: SLA 페널티·인센티브, 변경 우선순위·일정, 차기 인계 범위·일정

### Where (어디서)
- 원격 운영 (대부분), 현장 상주 (일부 사업)
- 모니터링: 통합 대시보드 (Grafana·Datadog·자체 등)
- 보고: 월간 운영위 (대면)

### Why (왜)
- **SLA 미달 = 페널티 + 신뢰 손실 + 차기 재계약 불리**.
- **변경 통제 부재 = 무상 추가 작업 폭주 + 운영 정체**.
- **차기 인계 부실 = 업계 평판 + 차기 입찰 시 우리도 당함**. (역지사지)

### How (어떻게)
1. 운영계획서 작성 (조직·SLA·KPI·절차·일정)
2. 모니터링·알림 구축 (장애 사전 인지)
3. 일상 운영 (장애 대응·변경 처리·정기점검·백업)
4. 월간 SLA 보고 + 운영위
5. 차기 갱신 또는 인계 협의 (3~6개월 전)
6. 차기 인계 (계약 종료 시)

## 6. 리스크 & 흔한 실수

| 리스크 | 영향 | 대응 |
|---|---|---|
| SLA 정량 정의 부재 | 페널티·평가 분쟁 | 계약 시점에 측정 방법까지 정의 |
| 모니터링 부족 | 사용자가 먼저 인지 → 신뢰 손실 | 운영 첫 주 모니터링 강화 |
| 변경 무절차 수용 | 운영 정체·SLA 미달 | 절차 강제 + 긴급/일반 분리 |
| 차기 인계 정보 통제 (악의) | 업계 평판 손상 + 차기 입찰 시 보복 | 선의의 협조 + 노하우는 정당 보호 (영업비밀) |
| 발주사가 우리 노하우를 차기 견적에 사용 | 부당이득 | 인계 산출물에 영업비밀 표시 + 사용 범위 합의 |
| 우리 인력 이탈 (장기 운영) | 노하우 유실 | 런북·문서화 강제 + 신규 인력 트레이닝 |
| 보안 사고 (장기 잔존 계정) | 책임 분쟁 | 분기별 계정 점검 + 회수 |
| 재계약 협의 지연 | 갱신 공백·인력 유실 | 종료 6개월 전 협의 시작 |
