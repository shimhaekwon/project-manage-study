## 3. 주요 내용 (As-Is)

### 3.1 현재 업무 흐름

- 고객 문의 채널: 이메일 (helpdesk@a.com), 전화 (월간 1,500건), 일부 사내 메신저
- 처리 방식: 받은 메일을 상담사가 수동 분배 → 답변 → 회신
- 평균 처리 시간: 측정 안 됨 (시스템 부재)

### 3.2 정량 지표 (월간 추정)

| 항목 | 수치 |
|---|---|
| 월간 문의 | 약 1,500건 (성수기 2,200건) |
| 누락·재문의 (고객 1주 후 재요청) | 약 60건 (4%) |
| 중복답변 | 월 8~12건 |
| 평균 1차 답변 소요 | 12~36시간 (편차 큼) |
| 상담사 수 | 5명 (정직원 3 + 파트타임 2) |

### 3.3 주요 Pain Point (상담팀장 직접 인용)

> "메일 한 건이 5명 메일함에 흩어져 있어요. 누가 처리했는지 모릅니다."
> "고객이 1주 후 '왜 답변 없냐'라고 다시 보내는 경우가 한 달에 60건쯤. 이게 가장 큰 문제."
> "통계가 없어서 임원 보고 때 매번 손으로 카운트합니다."

## 4. 결정사항 (To-Be)

### 4.1 통합 채널

- 단일 시스템 (Helpdesk Lite)으로 통합
- 이메일·전화 채널은 점진적 폐기 (Phase 1에서는 시스템만 구축, 채널 폐기는 Phase 2)

### 4.2 SLA 정책 (확정)

| 항목 | 합의 |
|---|---|
| SLA 응답 시간 | **24시간 (1차 답변 기준)** |
| SLA 재기산 | REOPENED 시 **재기산하지 않음** (최초 접수 기준 유지) |
| SLA 임박 알림 | 마감 4시간 전 자동 이메일 발송 (FR-INQ-004) |
| 알림 대상 | **전체 AGENT** (또는 ADMIN 설정 그룹) |
| SLA 미달 정의 | sla_due_dt 경과 + status = NEW |

> **결정 근거**: 상담팀장 — "재기산하면 상담사가 일부러 답변 늦추고 다시 답변하는 도덕적 해이 우려"
