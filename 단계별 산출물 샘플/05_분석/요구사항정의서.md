## 1. 개요

### 1.1 목적
본 문서는 사내 고객 Q&A 시스템(가칭 Helpdesk Lite)의 기능·비기능·데이터·인터페이스 요구사항을 명세하고, 후속 설계·개발·테스트·검수 단계의 추적 기준선(Baseline)을 확정한다.

### 1.2 범위
- **In Scope**: 문의 등록 / 답변 / 검색 / 이메일 알림 / SLA 통계
- **Out of Scope (Phase 2)**: AI 자동답변, 챗봇, 외부 고객사 직접 접속

### 1.3 대상 독자
발주사 PM·정보화팀·현업 / 수행사 PM·PL·설계자·개발자·QA / 감리

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 문의(Inquiry) | 고객이 등록하는 질의·요청 단위 |
| 답변(Answer) | 상담사가 작성하는 회신. 1 문의 1 답변 원칙 (REOPENED 시 추가 답변 가능) |
| SLA | Service Level Agreement. 본 시스템에서는 **최초 접수 시각 기준 24시간 이내 1차 답변**. REOPENED 시 SLA는 재기산하지 않는다. |
| GUEST / AGENT / ADMIN | 사용자 역할 (각각 고객 / 상담사 / 관리자) |
| Baseline | 본 v1.0 승인 시점의 요구사항 집합. 이후 변경은 변경관리 절차 적용 |

## 3. 기능 요구사항 (FR)

### 3.1 FR-INQ-001 — 문의 등록

| 항목 | 내용 |
|---|---|
| 요구사항 ID | FR-INQ-001 |
| 요구사항명 | 문의 등록 |
| RFP 출처 | RFP §4.1.1 / 제안서 §3.4.1 |
| 우선순위 | 필수 (M) |
| 요구 내용 | GUEST가 제목·내용·카테고리·첨부를 포함한 문의를 등록한다. 등록 즉시 status=NEW, sla_due_dt = 등록시각 + 24h 자동 산출. |
| 입력 | title (1~200자, 필수), content (1~5000자, 필수), category_cd (필수, CATEGORY 코드값), attachments (0~5개, 각 ≤10MB) |
| 출력 | 등록 결과 (inquiry_id, sla_due_dt) / 실패 시 사유 코드 |
| 제약 | 동일 GUEST가 1분 내 동일 제목·내용 등록 시 중복 차단 |
| 가정·전제 | 사용자 인증·권한 체크는 인증 모듈이 사전 처리 |
| 수용 기준 | (1) 정상 입력 시 inquiry 1건 + attachment N건 1트랜잭션 생성 (2) 검증 실패 시 INSERT 없음 (3) sla_due_dt 정확히 등록시각 + 24h |
| 검증 시나리오 ID | UT-INQ-001~005, IT-INQ-001 |

### 3.2 FR-INQ-002 — 답변 작성

| 항목 | 내용 |
|---|---|
| 요구사항 ID | FR-INQ-002 |
| 요구사항명 | 답변 작성 |
| RFP 출처 | RFP §4.1.2 / 제안서 §3.4.2 |
| 우선순위 | 필수 (M) |
| 요구 내용 | AGENT가 NEW 또는 REOPENED 상태의 문의에 답변을 작성한다. 답변 등록 시 문의 status를 ANSWERED로 자동 전이한다. GUEST에게 답변 완료 이메일이 자동 발송된다. **SLA는 최초 1차 답변 기준으로 측정**하며, REOPENED 발생 시 추가 답변은 허용되되 SLA를 재기산하지 않는다. |
| 입력 | inquiry_id (필수, 권한 검증), content (1~5000자, 필수) |
| 출력 | 답변 결과 (answer_id) / 실패 시 사유 코드 |
| 제약 | (1) status ∈ {NEW, REOPENED}만 답변 가능 (2) 동일 inquiry_id에 동시에 2명 이상 답변 시 낙관적 락(version 컬럼)으로 충돌 감지 |
| 가정·전제 | 이메일 발송은 외부 SMTP가 정상이라고 가정. SMTP 실패 시 재시도 큐에 적재 (FR-INQ-004 처리 모듈 공유) |
| 수용 기준 | (1) 답변 등록 + 문의 상태 전이 1트랜잭션 (2) 이메일 발송은 트랜잭션 외부에서 비동기 처리 (3) 동시 답변 시 1건만 성공, 다른 건은 CONFLICT 응답 |
| 검증 시나리오 ID | UT-INQ-006~010, IT-INQ-002 |

### 3.3 FR-INQ-003 — 문의 검색

| 항목 | 내용 |
|---|---|
| 요구사항 ID | FR-INQ-003 |
| 요구사항명 | 문의 검색 |
| RFP 출처 | RFP §4.1.3 / 제안서 §3.4.3 |
| 우선순위 | 필수 (M) |
| 요구 내용 | AGENT·ADMIN이 키워드(제목·내용)·카테고리·상태·기간으로 문의를 검색·정렬·페이징 조회한다. GUEST는 본인 문의만 조회 가능. |
| 입력 | keyword (선택, 1~100자), categoryCd (선택), status (선택, NEW/ANSWERED/REOPENED/CLOSED/CANCELLED), regDtFrom/To (선택), page (≥0), size (1~100), sort (reg_dt/sla_due_dt 등) |
| 출력 | items[], page, size, total |
| 제약 | (1) 키워드 검색은 LIKE 또는 전문검색 인덱스 활용 (2) 본인 문의 한정은 reg_id = 로그인 사용자 ID 자동 주입 |
| 가정·전제 | 검색 인덱스는 운영 환경에서 사전 생성됨 (`IX_STATUS_SLA`, `IX_CATEGORY`) |
| 수용 기준 | (1) 응답시간 95%ile ≤ 0.5초 @100 TPS (2) 권한별 데이터 노출 범위 정확 (GUEST 본인만, AGENT 전체) (3) 페이징·정렬 결과 정합 |
| 검증 시나리오 ID | UT-INQ-011~015, IT-INQ-003 |

### 3.4 FR-INQ-004 — SLA 임박 자동 이메일 알림

| 항목 | 내용 |
|---|---|
| 요구사항 ID | FR-INQ-004 |
| 요구사항명 | SLA 임박 자동 이메일 알림 |
| RFP 출처 | RFP §4.2.3 / 제안서 §3.4.4 |
| 우선순위 | 필수 (M) |
| 요구 내용 | 문의 status가 NEW이고 sla_due_dt까지 4시간 이내 남은 건을 매시각 스캔하여 **전체 AGENT (또는 ADMIN이 설정한 알림 대상 그룹)** 에게 이메일 알림을 발송한다. |
| 입력 | (배치) 현재시각 |
| 출력 | 발송 대상 건수·성공·실패 카운트, 실패 건은 재시도 큐 |
| 제약 | (1) 동일 문의 알림은 1회만 (중복 발송 금지) (2) 이미 ANSWERED·CLOSED·CANCELLED 상태는 발송 제외 (3) **REOPENED는 SLA를 재기산하지 않으므로 알림 대상에서 제외** |
| 가정·전제 | 사내 SMTP 서버 정상 / NTP 시계 동기화 (운영팀 책임) |
| 수용 기준 | (1) 알림 정확도 100% (대상 누락·오발송 0) (2) 임박 시점 ±5분 이내 발송 (3) SMTP 실패 시 재시도 3회·실패 시 운영 알림 |
| 검증 시나리오 ID | UT-INQ-016~020, **IT-INQ-SLA-007** (E2E) |

### 3.5 FR-INQ-005 — SLA 통계

| 항목 | 내용 |
|---|---|
| 요구사항 ID | FR-INQ-005 |
| 요구사항명 | SLA 통계 |
| RFP 출처 | RFP §4.2.4 / 제안서 §3.4.5 |
| 우선순위 | 중요 (S) |
| 요구 내용 | ADMIN이 일·주·월 단위로 (1) 접수 건수, (2) 평균 1차 답변 소요시간, (3) SLA 준수율(%), (4) 카테고리별 분포를 조회한다. |
| 입력 | 기간 단위(D/W/M), 시작일·종료일, 카테고리 필터(선택) |
| 출력 | 시계열 통계 + 카테고리별 분포 |
| 제약 | 통계는 매일 02:00 배치로 사전 집계 테이블에 적재. 실시간 조회는 사전 집계 + 당일 분 합산. |
| 가정·전제 | 통계 조회는 ADMIN 전용 |
| 수용 기준 | (1) 응답시간 95%ile ≤ 1초 (2) 사전 집계 vs 실시간 합산 결과 일치 (3) 권한 검증 정확 |
| 검증 시나리오 ID | UT-INQ-021~023, IT-INQ-005 |

### 3.6 FR-INQ-006 — 문의 취소

| 항목 | 내용 |
|---|---|
| 요구사항 ID | FR-INQ-006 |
| 요구사항명 | 문의 취소 |
| RFP 출처 | RFP §4.1.4 / 변경관리 CR-2026-001 |
| 우선순위 | 필수 (M) |
| 요구 내용 | GUEST가 본인이 등록한 문의를 NEW 상태에서 취소할 수 있다. 취소 시 status가 CANCELLED로 전이되며, 발송 대기 중인 SLA 알림이 있으면 취소된다. |
| 입력 | inquiry_id (필수, 본인 소유 검증) |
| 출력 | 취소 결과 (성공/실패) |
| 제약 | (1) status = NEW 인 경우에만 가능 (ANSWERED·REOPENED·CLOSED·CANCELLED는 거부) (2) 본인 문의에 한정 (다른 GUEST의 문의 취소 불가) (3) AGENT·ADMIN은 별도 관리 기능에서 처리 (본 FR 범위 외) |
| 가정·전제 | 인증·권한 사전 처리 |
| 수용 기준 | (1) NEW → CANCELLED 전이 1트랜잭션 (2) 권한 외 시도는 403 응답 (3) SLA 알림 큐에서 해당 건 제거 |
| 검증 시나리오 ID | UT-INQ-024~026, IT-INQ-006 |

## 5. 데이터 요구사항 (DR)

### 5.1 핵심 엔티티 (5개)

| 엔티티 | 핵심 속성 | 비고 |
|---|---|---|
| **INQUIRY** | inquiry_id(PK), title, content, status, category_cd(FK→CATEGORY), sla_due_dt, reg_id(FK→USER), reg_dt, version | 상태: NEW/ANSWERED/REOPENED/CLOSED/CANCELLED |
| **ANSWER** | answer_id(PK), inquiry_id(FK→INQUIRY), content, agent_id(FK→USER), reg_dt | 1 문의 N 답변 (REOPENED 대응) |
| **ATTACHMENT** | attachment_id(PK), inquiry_id(FK→INQUIRY), file_name, file_path, file_size, content_type, reg_dt | 등록 1회·삭제 ON DELETE CASCADE |
| **USER** | user_id(PK), login_id, password(BCrypt), name, role, dept, email | role: GUEST/AGENT/ADMIN |
| **CATEGORY** | category_cd(PK), category_nm | 코드값 예: PRODUCT/DELIVERY/REFUND/ETC |

### 5.2 관계
- INQUIRY 1:N ANSWER (REOPENED 시 추가 답변)
- INQUIRY 1:N ATTACHMENT (ON DELETE CASCADE)
- USER 1:N INQUIRY (작성자, reg_id)
- USER 1:N ANSWER (상담사, agent_id)
- CATEGORY 1:N INQUIRY

### 5.3 데이터 보존·이행
- 신규 시스템이므로 이행 데이터 없음 (Phase 1)
- 보존: 문의·답변 5년, 첨부 1년, 로그 3개월(감사 1년)

## 7. 가정·제약사항

| # | 항목 |
|---|---|
| A1 | 사용자는 사내 사원 계정으로 사전 등록된 자만 사용 (Phase 1, 외부 고객 직접 등록 없음) |
| A2 | 사내 SMTP 서버는 운영팀이 SLA 99% 이상 보장 |
| A3 | NTP 시계 동기화는 인프라팀 책임 |
