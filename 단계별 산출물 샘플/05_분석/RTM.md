# 요구사항 추적표 (RTM) — Helpdesk Lite

## 1. 목적

본 RTM은 RFP·요구사항부터 설계·개발·테스트·검수까지의 **추적성**을 한 줄도 끊기지 않게 유지한다. 끊기는 곳이 사고 발생 지점이다. 단계별 책임자가 해당 컬럼을 채워나가며, 09 검수 단계에서 양측이 전수 점검한다.

## 2. 갱신 책임

| 컬럼 | 채우는 단계 | 책임자 |
|---|---|---|
| RFP ID, 요구사항 ID/명, 우선순위 | 05 분석 | 분석가 |
| 설계 산출물 ID | 06 설계 | 설계자 |
| 개발 모듈, 단위테스트 ID | 07 개발 | PL |
| 통합테스트 ID, UAT 결과 | 08 통합·UAT | QA |
| 검수 결과 | 09 검수 | 양측 PM |

## 4. 우선순위·상태 정의

| 우선순위 | 의미 |
|---|---|
| **M** (Must) | 필수 — 이행 미달 시 검수 불합격 |
| **S** (Should) | 중요 — 이행 권장, 미달 시 합의 |
| **C** (Could) | 권장 — 우선순위 조정 가능 |

| 검수 상태 | 의미 |
|---|---|
| (미검수) | 아직 검수 진입 전 |
| **검수중** | 09 단계 진행 중 |
| **PASS** | 양측 합의로 인수 |
| **FAIL** | 결함 잔존 → 재검수 또는 차기 보완 |

## 10. 메모

- **누락 시그널**: 어느 컬럼이든 빈 칸이 있다면 그 시점에 즉시 조사. "나중에 채우자"는 검수 단계에 폭탄으로 돌아온다.
- **변경관리 흔적**: CR-2026-001처럼 변경관리로 추가된 행은 RFP ID에 CR 번호를 적어 추적성 유지. (FR-INQ-006 행 참고)
- **본 RTM은 살아있는 문서**: 단계가 진행될 때마다 갱신되며, 09 검수 시점에는 모든 컬럼이 채워져 있어야 한다.
