## 2. 슬라이드 구성 (22장)

### 2.1 도입 (5장 / 0~3분)

| # | 제목 | 핵심 메시지 |
|---|---|---|
| 1 | 표지 | 회사 로고 + "사내 고객 Q&A 시스템 구축 제안" + 제출일 |
| 2 | 발표 개요 | 발표 흐름 1장 요약 (위 표) |
| 3 | 사업 이해 (As-Is) | 메일·전화 분산 → 누락·중복답변 → 통계 부재 |
| 4 | 사업 이해 (To-Be) | 통합 Q&A → SLA 24h 준수 → 통계로 차기 개선 기반 |
| 5 | **Win Theme** | (1) 6하원칙 추적성 (2) Mock-Impl Green (3) 변경관리 절차 합의 |

### 2.2 기술 접근 (7장 / 3~10분)

| # | 제목 | 핵심 메시지 |
|---|---|---|
| 6 | 시스템 아키텍처 (개요) | FE/API GW/BE 4모듈/DB/NAS/SMTP — 한 장 다이어그램 |
| 7 | 적용 기술·표준 | JWT·BCrypt·envelope·UPPER_SNAKE_CASE 에러코드·공통컬럼 |
| 8 | **차별화 #1 — 6하원칙 추적성** | RFP→FR→DSN→모듈→UT→IT→검수 RTM 한 줄 (사례 표) |
| 9 | **차별화 #2 — Mock-Impl Green** | 설계 단계 개발자 페르소나 롤플레이 → pingpong 사전 차단 |
| 10 | 보안·마스킹 | OWASP Top 10 + 마스킹 미들웨어 (화면·로그·내보내기) |
| 11 | 성능 보증 | 동시 200·화면 1초·API 0.5초 / k6 부하 테스트 + 인덱스 튜닝 |
| 12 | 가용·운영 | 99.5% / MTTR 4h / ELK + Grafana 모니터링 |

### 2.3 사업관리 (5장 / 10~15분)

| # | 제목 | 핵심 메시지 |
|---|---|---|
| 13 | 추진 체계 (RACI) | 양사 역할 매트릭스 |
| 14 | 일정 (4개월 + 마일스톤 5개) | 분석 1 + 설계 1 + 개발 1.5 + 테스트 0.5 |
| 15 | 인력 (등급·M/M·이력 요약) | 핵심 인력 5명 사진·경력 요약 (실적 어필) |
| 16 | **차별화 #3 — 변경관리 절차 합의** | 무상 추가 과업 0 → 양측 보호 |
| 17 | 위험관리 (Top 3) | SMTP 지연·UAT 가용성·마스킹 누락 + 대응 |

### 2.4 마무리 (5장 / 15~20분)

## 4. 예상 질문·답변 준비 (Top 8)

| # | 질문 | 답변 핵심 |
|---|---|---|
| Q1 | 4개월 너무 빠른 거 아닌가? | 분석 1 + 설계 1 + 개발 1.5 + 테스트 0.5 = 표준 산정. 첫 주 표준 동결로 후반 재작업 차단 |
| Q2 | 동급 인력 보장? | 제안 인력은 실제 투입 가능자. 교체 시 동급 사전 통보·승인 |
| Q3 | 보안 사고 시 책임 한도? | 계약 협상 의제 — 손해배상 한도 = 계약금액 명문화 협상 |
| Q4 | SMTP 외부 연계 실패 시? | 3회 재시도 + 운영 알림 + 재시도 큐 적재 (트랜잭션 외부 처리) |
| Q5 | 개인정보 마스킹은 어떻게? | 응답 미들웨어에서 일괄 처리 + ADMIN 별도 권한으로 원본 조회(감사 로그) |
| Q6 | 검수 기준이 모호하면? | 정량 기준(결함률·기능 100%·SLA 95%+) 명문화 협상, 무응답 시 자동 검수 간주 |
| Q7 | UAT 사용자 가용성은? | 킥오프 시 사용자·일정 사전 합의, 임원 백업 |
| Q8 | 1년 운영도 별도 견적인가? | 운영 계약은 별도. 안정화 1개월·하자 12개월은 본 견적 포함 |
