## 3. 권한 검증 정책 (구현 가이드)

### 3.1 검증 위치

| 계층 | 검증 내용 |
|---|---|
| API Gateway | JWT 유효성 + 역할 (Role) 1차 검증 |
| 컨트롤러 | 액션 권한 (CRUD × 리소스) 검증 |
| 서비스 | **본인 데이터 한정** (GUEST는 reg_id = 사용자ID) — 가장 중요 |
| DB | FK 무결성 (작성자·답변자 USER 존재 확인) |

### 3.2 본인 데이터 한정 원칙

GUEST는 다른 GUEST의 데이터에 접근 불가. 다음 코드 패턴 의무화:

```
// 잘못된 패턴 (취약)
SELECT * FROM INQUIRY WHERE INQUIRY_ID = ?

// 올바른 패턴 (안전)
SELECT * FROM INQUIRY WHERE INQUIRY_ID = ? AND REG_ID = ?  // 본인 검증
```

API-INQ-MY-001처럼 reg_id를 Query에서 받지 않고 **인증 사용자 토큰에서 자동 주입**.

### 3.3 권한 우회 시도 대응

| 시나리오 | 대응 |
|---|---|
| GUEST가 다른 GUEST 문의 ID로 조회 시도 | 403 FORBIDDEN + 감사 로그 |
| AGENT가 ANSWERED 상태 답변 작성 시도 | 409 CONFLICT (INVALID_STATE) |
| ADMIN 외 사용자가 통계 조회 시도 | 403 FORBIDDEN + 감사 로그 |
| 만료 토큰으로 접근 | 401 UNAUTHORIZED + 토큰 갱신 안내 |
| 위조된 토큰 | 401 + 감사 로그 (IP·User-Agent) |
