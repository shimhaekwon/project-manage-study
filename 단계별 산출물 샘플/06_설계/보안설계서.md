## 1. 보안 목표 (NFR-INQ-003)

- 비밀번호·세션·전송·저장의 다층 방어
- **개인정보 마스킹** (이메일·전화번호) — 화면·로그·내보내기(엑셀·CSV)
- OWASP Top 10 High/Critical 0건
- 감사 로그 1년 보존

---

## 2. 인증 (Authentication)

### 2.1 ID/PW 자체 인증

| 항목 | 정책 |
|---|---|
| 비밀번호 저장 | BCrypt (cost=10, 단방향) |
| 비밀번호 정책 | 8자 이상 / 영문·숫자·특수문자 2종 이상 / 90일 만료·이력 5개 재사용 금지 |
| 로그인 시도 제한 | 5회 연속 실패 시 30분 잠금 |
| 비밀번호 변경 | 본인 가능 / ADMIN은 임시 비밀번호 발급 (로그인 시 강제 변경) |

### 2.2 세션 (JWT)

| 항목 | 정책 |
|---|---|
| Access Token | JWT, 30분 유효, payload: {sub, role, name, exp, iat} |
| Refresh Token | 별도, 7일 유효, HttpOnly Cookie 저장 권장 |
| Token 서명 | RS256 (비대칭, 키 보안 우수) — 또는 HS256 (대칭, 단순). 본 사업은 HS256 (단순성) |
| Refresh 갱신 시 | 이전 Access 무효화 (블랙리스트 또는 jti 검증) |
| 로그아웃 | Refresh Token 폐기 (DB 또는 블랙리스트) |

### 2.3 시크릿 관리

- JWT 서명 키·DB 비밀번호·SMTP 비밀번호 등은 환경변수 또는 Vault (Parameter Store)
- 소스코드·Git에 절대 포함 금지 (사전 훅: detect-secrets)
- 분기 1회 키 회전 (운영팀)

### 3.1 RBAC 다층 검증

| 계층 | 검증 |
|---|---|
| API Gateway | JWT 유효 + 역할 1차 |
| 컨트롤러 | 액션별 (CRUD × 리소스) |

상세는 별도 산출물 (`권한매트릭스.md`) 참조.

## 4. 데이터 보호

### 4.1 전송 (In Transit)

| 영역 | 정책 |
|---|---|
| Browser ↔ Nginx | TLS 1.2+ (강제), HSTS 헤더 |
| 내부 통신 (Nginx ↔ App ↔ DB) | 사내망 폐쇄 + 가능 시 mTLS |
| SMTP | SMTPS (포트 465) 또는 STARTTLS |

### 4.2 저장 (At Rest)

| 데이터 | 저장 정책 |
|---|---|
| 비밀번호 | BCrypt (단방향) |
| 토큰 | DB 저장 시 Hash (단방향), 비교 시 토큰 hash 비교 |
| 첨부 파일 | NAS 평문 저장 (사내망 폐쇄 환경). 민감 파일은 압축·암호화 옵션 (Phase 2) |
| 개인정보 컬럼 (email) | 평문 저장 + 응답 시 마스킹. 추후 컬럼 단위 암호화 검토 (Phase 2) |
| DB 백업 | 백업 자체 암호화 (백업 도구 옵션) |

### 4.3 개인정보 마스킹 (핵심 요구)

| 대상 | 마스킹 규칙 |
|---|---|
| 이메일 | 첫 글자 + `***@도메인` (예: `k***@example.com`) |
| 이름 | 첫 글자 + `**` (예: `김**`) |
| 전화번호 | 가운데 4자리 `****` (예: `010-****-5678`) — 본 시스템 전화 미수집 (Phase 1) |
| 주민번호 | 본 시스템 미수집 |

**적용 위치**:
1. **응답 미들웨어** — 모든 API 응답 직전 자동 마스킹 (DTO 어노테이션 기반)
2. **로그 미들웨어** — App 로그 출력 직전 마스킹
3. **내보내기 (Excel·CSV)** — 통계 내보내기 모듈에서 마스킹 후 생성

**예외 (원본 조회)**:
- ADMIN의 사용자 관리 화면 (USER 마스터 조회) — 단, 감사 로그 적재
- 운영팀 디버깅 시 — DB 직접 조회 (감사 로그 별도)

## 5. 입력 검증·OWASP Top 10 매핑

| OWASP | 위협 | 대응 |
|---|---|---|
| A01 접근 통제 | 권한 우회 | 권한 매트릭스 다층 검증 (§3) |
| A02 암호 실패 | 평문 저장·약한 암호 | BCrypt + TLS + 키 회전 |
| A03 주입 | SQL Injection·XSS·OS Command | Prepared Statement / ORM Bind / 출력 인코딩 / 입력 화이트리스트 |
| A04 안전하지 않은 설계 | 위협 모델링 부재 | 본 보안설계서 + 분기 위협 검토 회의 |
| A05 보안 구성 오류 | 헤더·디렉터리 노출 | Nginx HSTS·CSP·X-Frame-Options 설정, 디렉터리 인덱싱 비활성 |
| A06 취약·구식 컴포넌트 | 의존성 취약 | 분기 1회 의존성 스캔 (npm audit·OWASP Dependency-Check) |
| A07 식별·인증 실패 | 무차별 대입·세션 탈취 | 5회 잠금 + JWT 짧은 만료 + IP 모니터링 |
| A08 SW·데이터 무결성 | 무결성 검증 부재 | 배포 시 서명 검증 (CI/CD) + 첨부 Magic Number 검증 |
| A09 로깅·모니터링 실패 | 침해 탐지 지연 | 감사 로그 1년 + ELK 알림 |
| A10 SSRF | 외부 요청 우회 | 본 사업 외부 요청 거의 없음 (SMTP만) — 화이트리스트 |

## 6. 첨부 파일 보안

| 항목 | 정책 |
|---|---|
| 확장자 | 화이트리스트 (png/jpg/jpeg/gif/pdf/doc/docx/xls/xlsx/zip) |
| Magic Number | 업로드 시 파일 헤더 검증 (확장자 위조 방지) |
| 크기 | 10MB / 파일, 5개 / 문의 |
| zip 내부 검사 | Phase 1 검사 안 함 (사내 신뢰 환경) — Phase 2 검토 |
| 다운로드 | 파일 경로 직접 노출 금지, 서버 스트림 응답 (`Content-Disposition: attachment`) |
| 파일명 인코딩 | RFC 6266 utf-8 (한글 파일명 안전) |

## 7. CSRF·XSS·CSP

| 항목 | 정책 |
|---|---|
| CSRF | SameSite=Strict Cookie + Double Submit Cookie 보조 |
| XSS | 입력 시 화이트리스트, 출력 시 HTML 이스케이프, Content-Type `application/json` 강제 |
| CSP | `default-src 'self'; script-src 'self'; img-src 'self' data:; ...` (Nginx 설정) |
| Click-Jacking | `X-Frame-Options: DENY` |
| MIME Sniffing | `X-Content-Type-Options: nosniff` |
| Referrer | `Referrer-Policy: same-origin` |

## 8. 감사 로그 (Audit Log)

### 8.1 적재 대상 (1년 보존)

| 이벤트 | 적재 정보 |
|---|---|
| 로그인·로그아웃 | userId, IP, User-Agent, 시각, 결과 (성공/실패/잠금) |
| 권한 변경 (USER.role) | 수행자, 대상, 변경 전후, 시각 |
| 문의 취소 (FR-INQ-006) | 취소자, inquiryId, 시각 |
| 통계 조회 (FR-INQ-005) | 조회자, 기간, 필터, 시각 |
| 사용자 관리 (CRUD USER) | 수행자, 대상, 시각 |
| ADMIN 원본 조회 (마스킹 우회) | 수행자, 대상, 시각, 사유 (선택) |
| 권한 우회 시도 (403) | IP, 시도 내용, 시각 |
| 첨부 다운로드 | 다운로더, fileId, 시각 |

### 8.2 저장·조회

- DB 별도 테이블 (`AUDIT_LOG`) + ELK 동시 적재
- ADMIN 화면에서 검색·조회 가능 (단, 감사 로그 자체 조회도 감사 적재)
- 1년 후 자동 삭제 (운영 정책)

## 9. 보안 사고 대응 절차

```
[침해 탐지 (모니터링·신고)]
       ↓
[Critical 알림 즉시 (SMS·메일·Slack)]
       ↓
[1차 대응 (15분 내) — 격리·차단]
       ↓
[양측 PM 1시간 내 보고]
       ↓
[원인 분석 (RCA) — 24h 내 1차 보고서]
       ↓
[항구 조치 + 재발 방지]
       ↓
[감사 로그 + 사후 보고서 (양측 임원·법무)]
```

| 사고 등급 | 정의 | 보고 |
|---|---|---|
| Critical | 개인정보 유출, 권한 우회 성공, 인증 우회 | 즉시 양측 임원 + 법무 |
| High | 권한 우회 시도 다수, 무차별 대입 의심 | 양측 PM 1시간 내 |
| Medium | 단발성 의심 행위 | 일일 요약 |
