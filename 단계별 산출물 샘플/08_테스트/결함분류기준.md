# 결함 분류 기준 + 인수 한도 합의서 — Helpdesk Lite

> 본 문서는 **검수 분쟁 방지의 핵심**이다. UAT 시작 전 양측 PM 서명 필수.

## 1. 결함 정의

**"결함(Defect)"이란**, 본 시스템이 (1) 요구사항정의서 v1.1 / (2) 설계 산출물 / (3) 변경요청서로 명문화된 변경 — 위 3개 중 어느 하나에 부합하지 않는 동작을 일컫는다.

**결함이 아닌 것**:
- 명문화되지 않은 추가 기능 요청 (변경관리 절차 대상)
- 사용자 운영·교육 부족 (교육·매뉴얼로 처리)
- 외부 의존 시스템 장애 (사내 SMTP·NAS 등 — 별도 책임)
- "단순한 개선 의견" (백로그 검토)

---

## 2. 심각도 (Severity) 정의

| 심각도 | 정의 | 예시 |
|---|---|---|
| **Critical** | 핵심 기능 사용 불가 / 데이터 유실·왜곡 / 보안 취약 노출 / 법규 위반 | 로그인 불가 / 답변 데이터 유실 / SQL Injection / 마스킹 누락 |
| **High** | 핵심 기능 일부 사용 불가 / 우회 절차 필요 / 성능 SLA 미달 | SLA 알림 미발송 / 검색 결과 누락 / API 응답 5초 초과 |
| **Medium** | 비핵심 기능 오류 / 화면 표시 오류 (의미 전달 가능) | 정렬 잘못됨 / 라벨 오타 / 색상 미세 차이 |
| **Low** | 미관·문구·편의성 / 대안 우회 손쉬움 | 폰트 크기 / 단어 통일성 / 줄간격 |

---

## 3. 우선순위 (Priority) 정의

| 우선순위 | 정의 | SLA |
|---|---|---|
| **P1** | 즉시 수정 (라운드 내) | 24h 이내 |
| **P2** | 이번 주 내 수정 | 7일 이내 |
| **P3** | 이번 단계 내 수정 | 단계 종료 전 |
| **P4** | 백로그 (안정화·하자보수 기간 처리) | 일정 합의 후 |

> 심각도 ≠ 우선순위. 예: Critical은 거의 항상 P1, 그러나 Low 중에도 일부 P2 가능 (예: 임원 보고 화면 라벨).

## 4. UAT 통과 기준 (인수 한도)

### 4.1 인수 의사 표명 조건

UAT 종료 시점에 다음을 모두 충족해야 발주사가 "인수 의사 확인서" 서명한다.

| 등급 | UAT 종료 시점 한도 | 합의 사항 |
|---|---|---|
| **Critical** | **0건** | 0건이 아니면 UAT 연장 또는 검수 보류 |
| **High** | **0건** | 동일 |
| **Medium** | **≤ 5건** (잔존, 안정화 1개월 내 해결 합의) | 합의서 첨부 |
| **Low** | **≤ 30건** (잔존, 하자보수 12개월 내 해결 합의) | 합의서 첨부 |

### 4.2 검수 합격 조건 (M5)

| 등급 | M5 시점 한도 |
|---|---|
| Critical | 0건 |
| High | 0건 |
| Medium | ≤ 5건 (안정화 종료까지) |
| Low | ≤ 30건 (하자보수 기간 처리) |

### 4.3 잔존 결함 처리 합의 양식 (별첨)

UAT 종료 시점 잔존 결함은 다음 양식으로 합의:

| 결함 ID | 심각도 | 제목 | 처리 시점 | 처리 책임 | 양측 서명 |
|---|---|---|---|---|---|
| (예) DEF-INQ-XXX | Medium | … | 안정화 +14일 | 수행사 | (양측 PM 서명) |

## 5. 결함 등록·처리 절차

### 5.1 등록 채널

- **JIRA** (사내 인스턴스, 프로젝트 코드: HDL)
- 양측 누구나 등록 가능 (UAT 사용자 12명도 직접 등록)
- 등록 시 필수 항목: 제목·재현 절차·기대 결과·실제 결과·환경·증빙 (스크린샷·로그)

### 5.2 분류·할당 절차

```
[등록]
   ↓ (24h 내)
[QA 1차 분류 — 심각도·우선순위 가배정]
   ↓
[양측 PM 결함 분류 회의 (UAT 일일 리뷰)]
   ↓
[수행사 PL 할당]
   ↓
[개발자 수정]
   ↓
[QA 검증]
   ↓
[Verified → Closed]
```

### 5.3 분류 회색 지대 (양측 의견 불일치)

- 분류 회색 지대는 **공동 검토 후 합의 문서화**
- 불일치 지속 시 양측 임원 결재 (운영위)

## 8. 분쟁 사례 사전 합의 (학습 효과)

| 시나리오 | 합의 |
|---|---|
| 발주사가 "이건 Medium이지 High다"라고 주장 | 분류 회의 → 양측 PM 합의 → 임원 결재 |
| 발주사가 잔존 결함 5건 초과 시 인수 거부 | 합의서로 5건 초과 사유 명시 + 수행사가 추가 노력 약속 |
| 수행사가 "이건 결함이 아닌 변경 요청"이라고 주장 | 요구사항정의서·설계서 인용으로 결함 여부 판단 + 부합 안 하면 변경관리 절차 |
| UAT 사용자가 결함 등재 폭주 (의견·요청 포함) | 1차 QA 분류로 결함/요청 분리 → 요청은 백로그 |
