## 2. 기능 통합 시나리오

### 2.1 IT-INQ-001 — 문의 등록 + 첨부 + SLA 알림 큐 적재

| 항목 | 내용 |
|---|---|
| 시나리오 ID | IT-INQ-001 |
| 관련 요구사항 | FR-INQ-001 / IR-INQ-001 |
| 사전 조건 | GUEST 1명 로그인, 카테고리 4개 등재, NAS 정상, SMTP Mock 정상 |
| 절차 | 1. SCR-INQ-FORM-001 진입 / 2. 제목·내용·카테고리 입력 + 첨부 2개 (jpg + pdf) / 3. [등록] 클릭 |
| 기대결과 | (1) inquiry_id 발급·status=NEW (2) sla_due_dt = REG_DT + 24h (3) ATTACHMENT 2건 NAS 저장 (4) notification_log에 SLA_4H_BEFORE 적재 (5) 등록자 화면 SCR-INQ-DTL-001로 이동 |
| 검증 방법 | API 응답 + DB 검증 + NAS 파일 확인 + 큐 검증 |
| 우선순위 | High |
| 자동화 | API 자동 |

### 2.2 IT-INQ-002 — 답변 등록 + 메일 발송 + SLA 알림 큐 제거

| 항목 | 내용 |
|---|---|
| 시나리오 ID | IT-INQ-002 |
| 관련 요구사항 | FR-INQ-002 |
| 사전 조건 | NEW 상태 문의 1건 (sla_due_dt 미경과), AGENT 1명 |
| 절차 | 1. AGENT가 SCR-INQ-DTL-001 진입 / 2. 답변 작성 / 3. [등록] |
| 기대결과 | (1) ANSWER 1건 INSERT (2) INQUIRY status=ANSWERED, version+1 (3) GUEST에 답변 메일 발송 (Mock SMTP 검증) (4) notification_log에서 SLA_4H_BEFORE QUEUED → 제거 |
| 검증 방법 | DB + Mock SMTP 메일 수신 + 큐 검증 |
| 자동화 | API 자동 + 메일 검증 (MailHog) |

## 3. E2E 시나리오 (가장 중요)

### 3.1 IT-INQ-SLA-007 — 문의 등록 → SLA 임박 → 답변 → 종료 (End-to-End)

| 항목 | 내용 |
|---|---|
| 시나리오 ID | **IT-INQ-SLA-007** |
| 관련 요구사항 | FR-INQ-001, FR-INQ-002, FR-INQ-004, IR-INQ-001 |
| 사전 조건 | (1) AGENT 3명 활성 (2) GUEST K 활성 (3) Mock SMTP (또는 운영 SMTP 시험 계정) (4) 시계 가속 가능 환경 (또는 sla_due_dt 직접 조작) |
| 절차 | **(1)** 14:00 GUEST K 문의 등록 (FR-INQ-001) — sla_due_dt = 다음날 14:00 / **(2)** 시계 +20시간 이동 (또는 sla_due_dt를 +4h로 수동 조작) — 현 시점 SLA 임박 / **(3)** 09:00 SLA 알림 배치 실행 (FR-INQ-004) → 전체 AGENT 3명에게 메일 발송 / **(4)** 메일 수신 검증 (Mock SMTP 인박스) / **(5)** AGENT가 SCR-INQ-DTL-001에서 답변 작성 (FR-INQ-002) / **(6)** GUEST K 화면 새로고침 → ANSWERED 상태 확인 / **(7)** 7일 경과 배치 (또는 last_answered_dt 수동 조작) → CLOSED 자동 전이 |
| 기대결과 | (1) 메일 3건 발송 (notification_log SENT × 3) (2) 동일 inquiry SLA 알림 1회만 (UNIQUE 제약) (3) 답변 1건 등록 + GUEST 메일 1건 (4) status NEW→ANSWERED→CLOSED 전이 정상 (5) **REOPENED 시나리오 변형**: 5번 직후 GUEST가 추가 질문 등록 → REOPENED → 추가 답변 → ANSWERED → CLOSED 검증 (6) **REOPENED 알림 미발송 검증**: 재발송 큐에 적재 안 됨 |
| 검증 방법 | API + DB + Mock SMTP 인박스 + 화면 |
| 자동화 | 80% 자동 (메일 수신 검증 도구 — MailHog API 사용) |
| 우선순위 | **Critical** (가장 학습 가치 큰 E2E) |

### 4.1 NFR-PERF-001 — 성능 부하

| 항목 | 내용 |
|---|---|
| 시나리오 ID | NFR-PERF-001 |
| 관련 요구사항 | NFR-INQ-001 |
| 도구 | k6 또는 JMeter |
| 사전 조건 | 운영 유사 환경, 데이터 1만건, 사용자 250명 |
| 절차 | (1) 200 VU 5분 — `GET /api/inquiries` (목록 조회) / (2) 100 VU 5분 — `POST /api/inquiries` (등록) / (3) 250 VU 5분 — 혼합 (마진 검증) |
| 기대결과 | (1) 95%ile 응답 ≤ 0.5초 (2) 100 TPS+ 지속 (3) 에러율 0% |
| 합격 기준 | 위 3개 모두 PASS |
