## 3. SLA 정의·측정

### 3.1 SLA 지표·페널티

| # | 지표 | 목표 | 페널티 (목표 미달 시) |
|---|---|---|---|
| 1 | 월간 가용률 | 99.5% | 99.5%~99.0%: 월 운영비 5% 감액 / 99.0% 미만: 10% 감액 |
| 2 | API 95%ile 응답 | ≤ 0.5초 | 월 평균 1초 초과: 5% 감액 |
| 3 | 화면 95%ile 응답 | ≤ 1초 | 월 평균 2초 초과: 5% 감액 |
| 4 | Critical 장애 1차 응답 | ≤ 15분 | 30분 초과 1건당: 10만원 |
| 5 | Critical 장애 복구 (MTTR) | ≤ 4시간 | 8시간 초과 1건당: 100만원 |
| 6 | 일반 문의 응답 | ≤ 1영업일 | 3영업일 초과율 5% 이상: 5% 감액 |
| 7 | 패치 적용 (Critical) | ≤ 7일 | 14일 초과: 분기 운영비 5% 감액 |

### 3.2 KPI 측정 방법

| 지표 | 측정 |
|---|---|
| 가용률 | (총 분 - 장애 분) / 총 분 × 100. 정기 점검 제외 |
| 응답 시간 | APM (Datadog) 데이터 (운영팀이 분기 1회 검증) |
| MTTR | 알림 시각 ~ 정상화 시각 (감사 로그) |
| 일반 문의 응답 | 티켓 시스템 (JIRA) 응답 시각 |

## 4. 운영 절차

### 4.1 모니터링·알림

| 도구 | 용도 |
|---|---|
| Grafana + Prometheus | 인프라·App 메트릭 실시간 |
| ELK | 로그 (App·Access·Audit) 검색·알림 |
| APM (Datadog 또는 New Relic) | 응답 시간·트랜잭션 추적 |
| Slack #helpdesk-ops | 알림 수신 (Critical·High 즉시) |
| SMS·전화 | Critical 장애 시 (운영 PM·당직) |

### 4.2 일상 운영

| 활동 | 빈도 |
|---|---|
| 모니터링 대시보드 점검 | 매일 09:00·14:00 |
| 일일 결함·이슈 점검 | 매일 17:00 |
| 주간 SLA·트래픽 검토 | 매주 금요일 |
| 월간 SLA 보고서 작성 | 매월 5일 (전월 마감 후) |
| 분기 운영위 보고 | 분기 1회 |
| 분기 키 회전·의존성 스캔 | 분기 1회 |
| 분기 백업 복구 시험 | 분기 1회 |
| 연간 외부 모의 침투 | 연 1회 |

### 4.3 장애 대응 절차

```
[감지: 모니터링 알림 또는 사용자 신고]
       ↓
[1차 대응 (당직, 15분 내)]
       ↓
[심각도 분류 + Slack·전화 알림]
       ↓
[Critical: 양측 PM 즉시 보고 (1시간 내)]
       ↓
[원인 분석 + 임시 조치 + 항구 조치]
       ↓
[복구 검증 + 사용자 안내]
       ↓
[24~72h 내 RCA 보고서 (장애보고서.md)]
       ↓
[재발 방지 (분기 회고)]
```

### 4.4 변경 배포 절차

| 변경 종류 | 절차 |
|---|---|
| 정기 변경 (기능·버그) | (1) 변경 요청서 (2) 영향 분석 (3) 발주사 승인 (4) 테스트 환경 검증 (5) Blue/Green 배포 (6) 모니터링 |
| 긴급 변경 (Critical 대응) | (1) 적용 (2) 24h 내 사후 승인 (3) 배포 후 모니터링 |
| 보안 패치 | (1) 평가 (Critical 7일·High 30일 SLA) (2) 변경 요청서 (3) 배포 |

## 5. 결함·이슈 관리

| 분류 | 대응 |
|---|---|
| 운영 중 발견 결함 (수행사 귀책) | (운영 계약 범위 내 무상 처리) |
| 운영 중 발견 결함 (외부 의존·발주사 귀책) | 별도 협의 (운영 계약 외) |

| 운영 자체 작업 (모니터링·점검·백업) | 운영 계약 범위 |
